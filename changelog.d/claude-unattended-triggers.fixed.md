- **`claude.yml`'s job `if:` now allows `workflow_dispatch`/`schedule` events through** (#245). Previously the job's trusted-author gate only matched the four reactive, mention-triggered events (`issue_comment`, `pull_request_review_comment`, `pull_request_review`, `issues`), so a caller wired up for unattended/periodic invocation (e.g. a scheduled skill run) got a workflow that looked correctly configured but silently skipped the `claude` job on every run. The gate now also passes `workflow_dispatch`/`schedule` unconditionally: `workflow_dispatch` requires the dispatching actor to have repo write access, and a `schedule` (cron) trigger has no triggering actor at all, only existing because someone with write access committed its `cron:` config to the default branch, so no comment-body/author-association check is needed for either. The two post-steps that reply on the triggering issue/PR (`Acknowledge @claude mention`, `Post Claude's response if no code was committed`) are now gated to skip when there's no triggering issue/PR number, instead of running and failing on every unattended run. The agent's own prompt, and `examples/claude.yml`, were updated to explain that these unattended runs get no triggering issue/PR (no branch, draft PR, or reply comment), so the actual task belongs in `prompt-addendum` and any output must be persisted with tools `claude-args` grants.
